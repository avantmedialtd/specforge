# Rust workspace

Five crates: two library layers and three frontends. `openspec-core` holds pure primitives; `openspec-app` is the headless service layer that owns the stateful "brain"; `specforge` (Tauri), `specforge-tui` (ratatui) and `specforge-web` (browser) are thin skins over it.

**Where new logic goes.** Parsers, registries, caches and watchers belong in `openspec-core`. Anything stateful that more than one frontend needs — settings, service orchestration, dashboard assembly, quota — belongs in `openspec-app`. Frontend crates should only marshal arguments and call `AppService` / `SettingsStore`. Code parked in a frontend crate is invisible to the other two and is excluded from the mutation gate (`.cargo/mutants.toml`).

- **`crates/openspec-core/`** — no Tauri, no terminal. Cleanly testable from `cargo test`.
  - `registry.rs` — `WorkspaceRegistry` persists registered workspace folders to `workspaces.json`. Registration canonicalises the path and requires an `openspec/` subdirectory.
  - `parser.rs` — parses `tasks.md`, `proposal.md` titles, capability spec directories, and the four-artifact status (`proposal`/`design`/`tasks`/`specs[]`). Task-line format mirrors the artifex VSCode extension.
  - `cache.rs` — `WorkspaceCache`: a plain `HashMap<PathBuf, Vec<ChangeData>>`, passive (the watcher mutates it).
  - `watcher.rs` — `WatcherManager` runs one `notify` + `notify-debouncer-full` watcher per registered workspace, scoped to that workspace's `openspec/` subtree (recursive). On debounced batches it re-parses and emits `CacheEvent` over a tokio broadcast channel. The manager is cheaply cloneable; clones share state via `Arc`. The processing task holds a `Weak<Inner>` so the manager can be dropped cleanly.
  - **`CacheEvent` has far more than the three obvious variants.** Besides `Updated` / `ChangeAdded` / `ChangeArchived` there are `WorkspaceRemoved`, the aggregator's `LogicalChangeAdded` / `LogicalChangeArchived` / `InstanceAdded` / `InstanceRemoved`, plus `GraphChanged` and `QuotaUpdated`. In a git repository the aggregator emits the `Logical*` pair, **not** `ChangeAdded` — code that only matches `ChangeAdded` silently does nothing there. Never write a wildcard arm over `CacheEvent` without deciding what each ignored variant means.
  - `self_write.rs` — `SelfWriteTracker` records paths the app just wrote so the watcher can ignore the resulting events.
  - `wsl.rs` + WSL support — **Windows-only**. Workspaces in the WSL2 filesystem (reached via `\\wsl.localhost\<distro>\…`) are handled specially because the 9P share is deaf to `ReadDirectoryChangesW` and hostile to Windows `git.exe`. `wsl.rs` is pure path logic (detection, Linux↔UNC translation, `wsl.exe` argv building) — cross-compiled and unit-tested on every platform, inert off Windows. The two *backends* are `#[cfg(target_os = "windows")]`-gated: `watcher.rs` swaps in a `notify::PollWatcher` (re-scan cadence default **10s**, configurable via `wslPollIntervalSecs`, surfaced only on Windows), and `git.rs`'s `git_command(GitAnchor, args)` chokepoint routes every git call through `wsl.exe -d <distro> git …`, translating paths back to UNC. macOS/Linux builds carry none of this. `paths::canonicalize` (dunce-backed) is used at every `RepoId`-forming site so verbatim/UNC forms never split one repo into two identities. The 9P-runtime behaviour needs a real Windows+WSL2 box to verify.
    **No CI job compiles those `cfg(windows)` backends at all** — every runner is `ubuntu-latest` — so they can be broken by a refactor or a dependency bump without a single job going red. Compile-check them before you trust such a change: `cargo check --target x86_64-pc-windows-msvc -p openspec-core --all-targets` (add `clippy … -- -D warnings` to catch a deprecation, which CI treats as an error). The same trick is worth using for Linux from a macOS checkout — `--target x86_64-unknown-linux-musl` — because a dependency's per-platform type aliases can differ from macOS's; `notify-debouncer-full`'s `RecommendedCache` is `FileIdMap` on macOS and `NoCache` on Linux, so a type that compiles locally can still fail on the runner.
  - `types.rs` — `serde(rename_all = "camelCase")` on the structs that cross the IPC boundary, but **string-valued enums use `kebab-case`** (see `PaletteColor`). Harmless while every variant is one word; a multi-word variant would silently break the matching union in `src/types.ts`.
  - Also here, and larger than everything above: `repo_view.rs`, `git.rs`, `dashboard.rs`, `activity_log.rs`, `presentation.rs`, `repo_monitor.rs`, `repo_cache.rs`, `identity.rs`, `graph.rs`, `garden.rs`, `files.rs`, `paths.rs`. Working-tree status, the commit graph, dashboard assembly, the activity log and per-row presentation/disable state all live in these — check before adding a module.

- **`crates/openspec-app/`** — the headless application service. Depends on neither Tauri nor a terminal, so orchestration stays testable and identical across frontends.
  - `service.rs` — `AppService`: dashboard assembly, first-launch backfill/seeding, watcher lifecycle, link resolution.
  - `settings.rs` — file-backed `AppSettings` + `SettingsStore` + `WebServerConfig`, shared by all three frontends. **Launch-on-login is not stored here** — it lives in the OS via `tauri-plugin-autostart` (driven from `crates/specforge/src/commands.rs`) and is queried fresh each time.
  - `events.rs` — **the source of truth for every event name and payload shape** (`cache-updated`, `change-added`, `change-archived`, `workspace-removed`, `logical-change-*`, `instance-*`, `graph-changed`, `quota-updated`, `workspace-presentation-updated`, and the macOS-only `toggle-sidebar` / `toggle-commit-rail`). `event_envelope` maps a `CacheEvent` to its wire form. Both the Tauri forwarder and the web SSE bridge go through here; `src/types.ts` re-declares the same string literals by hand.
  - `config.rs` — `config_dir()` and `APP_IDENTIFIER` (`com.avantmedia.specforge`). Every instance resolves the same directory, which is why concurrent worktree apps share state.
  - `quota.rs` / `chatgpt_quota.rs` — the opt-in usage pollers (off by default). These are the app's **only** runtime network calls.

- **`crates/specforge/`** — Tauri shell. Thin by design.
  - `lib.rs` — the `run()` entry point. Order matters: install the event forwarder *before* populating the cache (initial `add_workspace` calls don't emit `Updated`, but later edits do — so the forwarder needs to be live first). Cache is populated synchronously via `block_on` so the frontend's first `get_changes` doesn't race a watcher startup. Also holds the `tauri::generate_handler![…]` list — a new command must be registered there.
  - `commands.rs` — `#[tauri::command]` handlers that deserialize args and call `AppService` / `SettingsStore`. The path-traversal guard on artifact reads lives in the shared layer, not here — don't re-add a second one.
  - `events.rs` — only the Tauri forwarding sink (`spawn_event_forwarder`), which maps each `CacheEvent` through `openspec_app::event_envelope` and emits it. Names and shapes belong to `openspec-app`.
  - `tray.rs` + `tray_icon.rs` — system tray. The badge updater subscribes to the same `CacheEvent` stream as the forwarder; on macOS the badge is set via `set_title`. There are **two** glyphs — `icons/tray-icon.svg` (`TrayGlyph::Default`) and `icons/tray-specs.svg` (`TrayGlyph::Specs`, shown when any active change has capability specs, flipped live by `spawn_tray_glyph_updater`). Edit both together. Each is rasterized per-monitor at the active scale factor and re-rasterized when the window moves between displays with different scales. macOS template rendering requires **pure black + alpha** — `rasterize` debug-asserts every output pixel has R=G=B=0.
  - `notifications.rs` — desktop notifications fire on `ChangeAdded` **and on `LogicalChangeAdded`** (the variant that actually fires for git repos), plus the archive counterparts; `Updated` never notifies, by design. Gated by `settings.notifications_enabled` and further suppressed per-row for parked/disabled rows — check both before concluding a notification path is broken.

- **`crates/specforge-tui/`** — the terminal frontend. One binary, three faces: the interactive TUI, `--status` (snapshot and exit) and `--line` (one ambient status line). All three drive the same in-process `AppService`, with no IPC.

- **`crates/specforge-web/`** — the local web server: an embedded mode the desktop app's serve toggle drives, and a standalone binary `specforge-serve`, released alongside `specforge-tui` for macOS/Linux/Windows (see `release-pipeline`).
  - `dispatch.rs` is the `/api/invoke` command table — **one arm per Tauri command**. See `src/CLAUDE.md` for the parity rule; a missing arm is a runtime-only failure.
  - Bind resolution is `--bind <addr>`, else the `SPECFORGE_WEB_BIND` env var, else `127.0.0.1`. It is deliberately never a `WebServerConfig` field, because that struct is shared with the desktop app's embedded toggle — don't add a settings control for it by reflex. A non-loopback bind disables the request-authority allowlist; see the `web-ui` capability spec for the trust-boundary contract.

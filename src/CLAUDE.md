# Frontend

**The same bundle runs in two hosts.** `src/api.ts` gates on `isTauri()`: `invokeLogged` dispatches to Tauri's `invoke` in the desktop app and to `webInvoke` (`POST /api/invoke`) when served by `specforge-web`. So **adding a command touches four places**, not one:

1. `src/api.ts` — the wrapper
2. `crates/specforge/src/commands.rs` — the `#[tauri::command]` handler
3. `crates/specforge/src/lib.rs` — the `tauri::generate_handler![…]` list
4. `crates/specforge-web/src/dispatch.rs` — a match arm in the `/api/invoke` table

Miss step 4 and the command works in `bun tauri dev` and fails at runtime in the browser with `unknown command: X`. Neither `tsc` nor `cargo` catches it, and the served web UI is the preferred path for visual verification — so this is the failure you are most likely to hit.

One command breaks that rule on purpose: `open_pull_request` has **no** `dispatch.rs` arm, so the web transport has no operation that opens a URL on the serving host (`web-ui`: *Link Handling in the Browser Skin*). A browser-skin pull-request row is a `target="_blank" rel="noopener noreferrer"` link instead, and `dispatch::tests` pins the command as unknown there. Don't "fix" the missing arm.

Events split the same way: `listenLogged` uses Tauri `listen` in the desktop app and an `EventSource` against `/api/events` in the browser (served by `crates/specforge-web/src/sse.rs`). A new event name needs the SSE side too. Names and payload shapes are owned by `crates/openspec-app/src/events.rs`; `src/types.ts` re-declares the same string literals by hand. The pull-request panels brought three: `bitbucket-pull-requests-updated` and `github-pull-requests-updated` (`CacheEvent`s, payload-less — re-read with `get_bitbucket_pull_requests` / `get_github_pull_requests`; the provider-less `pull-requests-updated` and `get_my_pull_requests` are retired and must not come back), and `pull-request-panel-moved` (a direct emit from `set_bitbucket_panel_position` and `set_github_panel_position` on both transports, carrying `{ provider, position }` — a listener re-seats only the named provider's panel).

**Two pull-request panels, four slots, no pane of their own.** `App.tsx` renders `<PullRequestPanel provider="bitbucket" />` and `<PullRequestPanel provider="github" />`, each at one of four JSX positions chosen by that provider's persisted position setting (`PanelPosition` in `src/types.ts`; `bitbucketPosition` / `githubPosition` in `App`): `left-top` (between the Dashboard button and `.sidebar-tree`), `left-bottom` (the default for both — between `.sidebar-tree` and the Archive button), and `right-top` / `right-bottom` (first or last child of the `.rail-column` wrapper around `GraphRail`, which exists only while a panel is positioned in the rail). `panelsAt(slot)` renders BitBucket's then GitHub's, so two panels sharing a slot always stack in that order. A panel hides with its pane, renders nothing while its feature is disabled, and its body is one height-bounded scroll container so the sidebar footer stays reachable. Each panel reports whether it renders through `onPresenceChange`; while a *present* panel sits in a pane, `App` adds `sidebar-tree--reserve` / `rail-column-graph--reserve`, which keeps the tree (or graph) a fifth of the viewport that the panels yield first — keyed on presence, never on position alone, so a default install (both off at `left-bottom`) lays out exactly as it did without the panels. The pure decisions (sections, counts, reserve) live in `PullRequestPanel.tsx` and are tested there. Collapsed state is per-provider `localStorage` view state (`specforge.pullRequestsCollapsed` for BitBucket, `specforge.githubPullRequestsCollapsed` for GitHub), never a setting.

**Pull requests ↔ worktrees.** `get_pull_request_links` (both transports — a pure in-memory read, unlike `open_pull_request`) returns which pull requests are linked to which tracked worktrees; the join lives in `openspec-app`, never here. It has no event of its own: `usePullRequestLinks(views)` (`src/hooks/`) re-reads it whenever `views` changes and on either `*-pull-requests-updated`, and `App` hands the snapshot to `DetailPane` (header chips) and both `PullRequestPanel`s (worktree markers). Three rules: a header pull-request chip is a SIBLING of `CopyableIdentity`, never inside it (the name's copy and single tab stop stay untouched); the switcher's `#n` marker is passive text inside the option's button, never a nested control; and a panel row's worktree marker is a sibling `<button className="pull-request-worktree">` beside the row control in a grid `<li>` — never inside the row's `<button>`/`<a>`, which cannot nest interactive content. An unlinked row carries no class and renders as before. The pure decisions — lookups, where a marker lands (`worktreeDestination`: the worktree's one change, else its most recently modified, else the repository file browser), and the wording — live in `src/pullRequestLinks.ts` and `PullRequestChip.tsx`, and are tested there.

**Tree selection.** The tree is two levels — a top-level row (repo group or flat workspace) and a change row — and stops there. The contract is the `TreeSelection` union in `src/types.ts`, three variants: `workspace`, `repo`, and `change` (which carries its `TreeContainer` plus the logical change name, never a worktree path). Selections are emitted from `src/components/WorkspaceTree.tsx`.

Adding a variant means updating **two** exhaustive switches in `App.tsx`, not `handleSelect` (which has no switch — it delegates): `repoIdForSelection` and `renderTargetForSelection`. Both are exhaustive over the union with no `default` arm, so `tsc` catches a missed one. There is no third switch: `scrollAnchorForSelection` and its silent `default: return null` are gone with the section and task rows, and `ScrollAnchor` is now the single kind `{ kind: "line"; line }`, produced inside `DocumentView` by the outline and by fragment links rather than by the tree.

**Which artifact and which instance is not a tree question.** A change row resolves to the change's *default artifact* of its *default instance* (`src/changeNavigation.ts` — the same module the header's tab strip reads, so a row click and the strip cannot disagree). Everything below the change — picking another artifact, picking another worktree — happens in the **change header** (`ChangeHeader` in `src/components/DetailPane.tsx`), which `App` places in live mode and `ArchiveView` places in read-only mode. Both write addresses through the existing `go()`, so history, deep links and reader windows are unaffected.

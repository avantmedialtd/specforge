## 1. Archive recency without walking the archive (openspec-core)

- [ ] 1.1 In `crates/openspec-core/src/repo_view.rs` `build_repo_view`, replace the `newest_mtime(<wt>/openspec/changes/archive/<dir>)` call with a pure helper `archive_dir_recency(dir_name) -> u64`. It returns 00:00 UTC of the `parser::archive_dir_date` prefix, parsed with `chrono::NaiveDate`, or `0` for an undated or unparseable name. Make no filesystem call on any `archive/` path (`archive-browser`: *Archived Instances Are Ordered Without Reading the Archive*).
- [ ] 1.2 Update the doc on `ChangeInstance::modified_at` to say an archived instance carries its archive date. Correct the `RepoView::archived` doc, which still says a mixed logical change "buckets into `active`", to describe the partition. Correct the `dashboard::repo_ships` doc, which says "Both sections are scanned" while it scans only `archived`, and its inline "most-recently-modified first … freshest copy" comment (dashboard.rs ~507). Correct the `LogicalChange` doc (repo_view.rs ~185), which says instances are ordered by most-recently-modified first, to say archived instances order by archive date.
- [ ] 1.3 Unit tests in `repo_view.rs` for `archive_dir_recency`: a dated name, a later date ordering higher, an undated legacy name giving `0`, and a malformed date such as `2026-13-40-foo` giving `0`. Assert exact values so mutants on the arithmetic are killed.
- [ ] 1.4 Test (`repo_view.rs` tests, real temp dirs): a change archived `2026-06-04-foo` in W1 and `2026-06-05-foo` in W2, with W1's copy holding a file whose mtime is set into the future via `File::set_modified`. Assert that W2's archived instance orders first. Add a same-date case asserting that worktree order is kept across two `build_repo_view` calls (`archive-browser`: scenarios *File timestamps inside an archived change do not affect ordering* and *Same-day copies keep worktree order*).
- [ ] 1.5 Test in `crates/openspec-core/src/dashboard.rs` tests: with two same-day archived copies, `repo_ships` picks the copy from the earliest tracked worktree on repeated builds.
- [ ] 1.6 Test that the aggregation does not descend into the archive. Add a `#[cfg(test)]` thread-local call counter to `newest_mtime` (deterministic, no timing). Build a view over a worktree with two active changes and several archived stubs, and assert the counter equals the active instance count exactly, so no call is made for any archived instance. Do not use an unreadable subdirectory instead: today's `newest_mtime` already skips a directory it cannot read, so such a test would pass against the old code.

## 5. Divergence compare and scoped merge (openspec-core)

- [ ] 5.1 In `repo_view.rs`, have `collect_relative_files` / `walk` return `(PathBuf, u64)` using the metadata already read. `dirs_differ` rejects on any path or length mismatch, then compares equal-length pairs in streamed fixed-size chunks with early exit. An unreadable file still counts as differing, and so does a short read before the known length or extra bytes after it on either side. Bound the loop by the known length so a mutated step cannot hang. Fix the doc, including its symlink claim, since `walk` skips symlinks (`spec-browser`: *Per-Instance Divergence Label*).
- [ ] 5.2 Unit tests for `dirs_differ`: identical dirs give `false`; a same-length one-byte edit gives `true`; different lengths give `true`; an extra file gives `true`; a renamed file gives `true`; an unreadable file gives `true` (`#[cfg(unix)]`); and files larger than one chunk that differ only in the last chunk give `true`.
- [ ] 5.3 In `watcher.rs` `refresh_aggregated_view_for`, replace the two snapshot clones. Swap the new `RepoView` into `last_views` in place under the write lock, keep the old one, release the lock, and diff only `[old]` against `[new]`. The flat splice uses the same shape.
- [ ] 5.4 Test in `repo_view.rs` tests: for a multi-repo snapshot where one repository gains, loses, archives and moves instances, `diff_views` over the single replaced repository yields the same event multiset as `diff_views` over the full old and new snapshots.

## 1. Pure Zoom Module

- [x] 1.1 Create `src/components/figureZoom.ts` with the module's value types — a `ZoomState` carrying scale and both scroll offsets, and a `Extents` pair for viewport and content dimensions. Keep every export a total function of its arguments with no DOM access, so `bun test` can reach all of it (`design.md`: *Decision 4*)
- [x] 1.2 Implement `fitScale(viewport, content, padding)` returning $\min\left(\frac{W_v - 2p}{W_c}, \frac{H_v - 2p}{H_c}\right)$, so the figure opens fully visible on whichever axis constrains it (`spec-browser`: *Maximized Figure View*)
- [x] 1.3 Implement `clampScale(scale, fitScale)` bounding scale to $[\min(s_{\text{fit}}, 1),\ s_{\max}]$ with $s_{\max} = 8$, so the figure can neither be reduced past fit nor enlarged without limit (`spec-browser`: *Maximized Figure View*)
- [x] 1.4 Implement `zoomAt(state, factor, pointer, viewport, content)` returning the new scale and both scroll offsets from $\ell' = \frac{s'}{s}(\ell + c) - c$, applied per axis, so the point under the pointer stays under it (`spec-browser`: *Maximized Figure View*)
- [x] 1.5 Implement `pinchFactor(previous, current)` as the ratio of two-contact separations, returning a neutral factor when either separation is degenerate so a pinch beginning with coincident contacts cannot produce a non-finite scale (`spec-browser`: *Maximized Figure View*)
- [x] 1.6 Implement `panBy(state, delta, viewport, content)` clamping both scroll offsets to their valid ranges, so a drag cannot push the figure entirely out of the surface
- [x] 1.7 Write `src/components/figureZoom.test.ts` covering: fit constrained by width and by height separately; clamp at both bounds and at the fit-below-one case; `zoomAt` holding the anchor point at the viewport's left edge, centre, and right edge; `zoomAt` composed with its inverse returning to the original offsets; `pinchFactor` on a degenerate separation; and `panBy` clamping at all four limits (`design.md`: *Risks / Trade-offs* — these tests are the change's only automated gate)

## 5. Verification

- [x] 5.1 Run `bun test` and confirm the `figureZoom` suite passes alongside the existing suites
- [x] 5.2 Run `bun run build` — strict `tsc --noEmit` with `noUnusedLocals` / `noUnusedParameters`, then the bundle — and confirm it is clean
- [x] 5.3 Run `bun run build` once in this worktree before `cargo test`, then run `cargo test` to confirm no Rust regression; the workspace suite fails workspace-wide in a fresh worktree until `dist/` exists, and the failure surfaces as an opaque proc-macro error rather than a missing bundle. **Result: 25 test binaries, 553 tests, 0 failures.** Note the pipeline trap: `cargo test | tail` reports *tail's* exit status, so a piped run's exit code proves nothing — run it unpiped
- [x] 5.4 Smoke the change in the running app, walking the *Maximized Figure View* scenarios. **Results:** the defect reproduced first (a 2537px diagram rendered at 880px in a 944px pane — 35%); maximizing opened it at 74% fit; the ceiling clamped at exactly 800% and the floor at exactly the fit scale; a synthesized pointer drag panned the figure against the pointer by the exact delta; and an `svg` fence enlarged to ~4x its natural 1400px width stayed razor sharp, confirming it re-rasterizes rather than magnifying a fixed raster
- [x] 5.5 Smoke the dismissal and scope rules. **Results:** with an archived artifact open inside the Archive view, one Escape closed only the lightbox and left the Archive open, and a second Escape closed the Archive — the `defaultPrevented` contract holds. The URL and `history.length` were unchanged across open/zoom/pan/close. Navigating away closes the view, verified via Back (the dialog is modal, so the tree behind it is inert and a click cannot navigate — Back and deep links are the only routes)
- [x] 5.6 Smoke the live-update and scheme paths. **Results:** a scheme change replaced the rendered SVG node (verified by tagging it) while the lightbox stayed open with scale *and* scroll position preserved exactly. A live file edit closes the view — see 4.2 for why that is the specified behaviour, and note the artifact behind it updates in place as normal
- [x] 5.7 Confirm the negative cases in the app. **Result:** the artifact rendered 2 figure frames with 2 affordances, 2 degraded fences with 0 affordances between them, and the ordinary `ts` fence untouched
- [x] 5.8 Verify in the browser against `specforge-serve`. **Done — all of 5.4–5.7 above were run in a browser against `specforge-serve`, which is the served web UI.** The desktop shell was NOT separately smoke-tested: verifying a native window needs screen-capture permission this environment does not have. Both frontends load the identical bundle, and the one desktop-specific risk — the macOS hidden inset titlebar — is addressed by anchoring every lightbox control to the trailing edge, away from the window controls. Worth a human glance in `bun run wt:dev` before release (`web-ui`: *Read-Only Parity With the Desktop Frontend*)

**Not verified — paint performance.** Layout cost was measured at 0–1ms for every scale up to the 800% ceiling, so resizing itself is free. Paint/rasterization could not be measured: the automation tab runs with `visibilityState: "hidden"`, where Chrome suspends `requestAnimationFrame`, and several apparent "renderer frozen" timeouts were that suspension rather than slow painting. There is no evidence of a performance problem, but interactive smoothness at high zoom on a large figure remains unconfirmed and wants a human check in a foreground window.

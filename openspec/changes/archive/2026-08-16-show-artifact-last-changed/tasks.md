## 1. The Service Returns a Modification Time

_This is the only mutation-gated file in the change (`.cargo/mutants.toml` scopes the gate to `openspec-core` + `openspec-app`, and `openspec-core` is not in the artifact-read path at all). Every line added here needs an assertion or a written exclusion._

- [x] 1.1 In `crates/openspec-app/src/service.rs`, add a serializable `ArtifactRead { body: String, modified_at: u64 }` with `#[serde(rename_all = "camelCase")]`, `modified_at` being unix seconds — the same encoding `ChangeInstance::modified_at` already uses, so the frontend has one time representation rather than two (proposal → Impact).
- [x] 1.2 Change `AppService::read_artifact` to return `Result<ArtifactRead, String>`. Take the metadata **before** reading the file, not after: a write landing mid-call then yields a modification time at or before the bytes' own, so the header can under-report but never claim content is fresher than it is (design.md D2).
- [x] 1.3 Leave `resolve_artifact_path` and its traversal guard untouched — the resolution and the authorization are unchanged, only what is returned from the resolved path (proposal → Impact).
- [x] 1.4 Decide and implement the unreadable-metadata case explicitly rather than by `unwrap_or`: if the body reads but `metadata()` or `modified()` fails, the read as a whole must not fail (the artifact is displayable) and a fabricated epoch time must not be reported as fact. Whatever is chosen, state it in the code comment so the next reader does not have to infer it from a fallback expression. **Decided:** `modified_at` is `Option<u64>`, `None` on any failure — absent metadata, a platform that tracks no modification time, and a pre-epoch stamp all fold to "no time to show". The read still succeeds. `u64` with a `0` fallback was rejected because the caller cannot distinguish a real epoch timestamp from a stand-in, so the header would render "1970" in the same confident tone it renders facts. Consequence: the TS mirror is `number | null` and the header renders no label when null — added as a spec scenario, see §5.6.
- [x] 1.5 Add tests in `crates/openspec-app/src/service.rs` covering: a successful read returns the file's own modification time, not the directory's and not a sibling's; writing the file and re-reading yields a strictly newer value; the existing traversal-guard and unregistered-workspace tests still reject before any metadata call. Assert on the returned value, not merely that the call succeeded — a test that ignores `modified_at` leaves 1.2's mutants alive.
- [x] 1.6 Run `cargo mutants --in-diff` against `origin/master` per the project runbook and confirm no survivor in `openspec-app`. A survivor means 1.5 does not actually pin the new line; add the assertion rather than excluding, unless the mutant is genuinely untestable — in which case record the reason in `.cargo/mutants.toml`. **4 mutants, 3 caught, 1 unviable, 0 survived.** Baseline green (`225s build + 23s test`), so the score is real rather than the false pass a red baseline produces. No exclusion needed in `.cargo/mutants.toml`.

## 4. The Relative Formatter

_A pure module with tests, alongside `changeIdentity.ts`. JSX is not exercised by `bun test` and a frontend-only diff short-circuits the mutation gate, so this is the only coverage this logic can get — the same reasoning that put `branchChipForWorktree` there._

- [x] 4.1 Add a pure formatter taking a modification time and a reference "now", returning the label text. Relative, at the granularity the elapsed interval warrants (`spec-browser`: *Change Identity Header in the Detail Pane* — "Last changed"). Added `src/lastChanged.ts`: `just now` → `N min ago` → `N hr ago` → `N day(s) ago` → `N mo ago` → `N yr ago`. Deliberately a fixed compact vocabulary rather than `Intl.RelativeTimeFormat`, whose output width varies by locale — the constant-width box in §6 needs a computable maximum, and the whole identity row is already hardcoded English.
- [x] 4.2 Floor the elapsed interval at zero, so a file stamped in the future renders as the present moment rather than as a future time (`spec-browser`: *…* — "A modification time in the future is not shown as future"; design.md D4).
- [x] 4.3 Export, from the same module, the cadence at which a given label should next be recomputed — never finer than the unit displayed, so a pane parked on a twelve-day-old artifact does not wake every few seconds (design.md D4). Keeping it beside the formatter means the tick and the text cannot disagree about the unit. **Bug found and fixed while testing:** bounding the delay by the next multiple of the current unit alone misses a *range* transition whose boundary is not a multiple of that unit. A year is 365 days and a month here is 30, so `12 mo ago` would have sat until day 390 before becoming `1 yr ago` — 25 days late. `nextTickDelayMs` now takes `min(next unit step, range end)`, which makes every transition correct by construction rather than by coincidence.
- [x] 4.4 Export the widest text the formatter can emit, so the reserved box in §6 is sized from the formatter itself rather than from a constant that drifts when the wording changes (design.md D5). `LAST_CHANGED_WIDEST = "29 days ago"` (11 chars). The row is monospace, so character count is an exact rendered width.
- [x] 4.5 Test: each unit boundary in both directions; the future-time clamp; that the cadence returned is never finer than the displayed unit; and that no producible label is wider than 4.4's declared maximum — the assertion that keeps the reserved box honest. 12 tests, 340 assertions. The strongest is a property sweep: at `now + nextTickDelayMs` the label differs, and one millisecond earlier it does not — which is what caught 4.3's bug.

## 10. Code-Review Fixes

_From `/code-review` on the finished branch. Eleven findings; the two marked **bug** were real defects in shipped code, not style._

- [x] 10.1 **bug — `setTimeout` overflow busy loop.** `nextTickDelayMs` returned up to 30 days (2,592,000,000 ms) in the months tier, above `setTimeout`'s WebIDL `long` ceiling of 2,147,483,647. Over the ceiling the delay coerces **negative** (`2592000000 | 0 === -1702967296`), so the timer fires immediately and the self-rescheduling chain becomes a render loop bounded only by the 4 ms nested-timeout floor — on every sidebar row older than 30 days, for roughly six days out of every thirty. Verified numerically before fixing. Clamped to `MAX_TIMEOUT_MS`; the existing "is always positive, so a tick can never busy-loop" test passed throughout, because positivity was never the failing property. New test sweeps 400 days plus 48 hours either side of the tier edge.
- [x] 10.2 **bug — a new artifact dated with the previous one's write.** `reduce`'s `select` branch retained `modifiedAt` while `changeId` and `chip` come from the render target and update synchronously, so for the length of one read the header showed the incoming change's name and branch beside the outgoing artifact's time — and stepping `proposal` → `tasks` within one change, that is exactly the sibling's write time the spec forbids reporting as this artifact's. `select` now clears it; the document is still retained, and the asymmetry is documented on the field. The original task 3.4 note arguing for retention was wrong: it reasoned about the document on screen and overlooked that the header's *identity* had already moved on.
- [x] 10.3 A future-stamped file scheduled a 60-second wakeup that recomputed the identical "just now", forever — the exact churn the module's contract disclaims. Scheduling now uses the **unclamped** delta and sleeps until the stamp becomes the present.
- [x] 10.4 `.row-mtime`'s tooltip still rendered `1970-01-01T00:00:00.000Z` for `modifiedAt === 0`, one hover away from the `—` the same hunk had just added — the application stating a fabricated date in the tone it states real ones. Guarded to match the text.
- [x] 10.5 The `.identity-changed` comment in `App.css`, the only explanation of where the inline `min-width` comes from, still pointed at `LAST_CHANGED_WIDEST` in `src/lastChanged.ts` — both deleted by 8.6. Retargeted to `RELATIVE_TIME_WIDEST` in `src/relativeTime.ts`.
- [x] 10.6 The memo rationale in `MarkdownView.tsx` and `DetailPane.tsx` claimed a tick re-renders `DetailPane`. It does not: the tick state lives in the `LastChangedLabel` leaf, so it never reaches `MarkdownView` with or without the memo. The memo is load-bearing for the *reducer* path — a modification-time-only `resolved` — and both comments now say so.
- [x] 10.7 `useTickingNow` called `setNow` unconditionally in its effect body, forcing a second render pass on every mount that `useState`'s initializer had already made unnecessary — hundreds of wasted leaf renders on a large sidebar, and again on every watcher batch. Re-anchoring is now guarded on the subject actually changing.
- [x] 10.8 `LastChangedLabel` re-implemented `RelativeTime` verbatim — the same two lines — inside the change that exists to stop exactly that. Both now share a `useRelativeTime(unixSeconds): string` hook, which also guarantees the header's text and its tooltip cannot disagree across a tick.
- [x] 10.9 The `dashboard` capability had no delta despite its rendered vocabulary changing, leaving the equivalence pinned from only one side. Added, including the previously unsanctioned behaviour where an entry with no recoverable instant rendered "archived" with nothing after it.
- [x] 10.10 The `cleared` guard's `modifiedAt === null` condition is genuinely unreachable under the field's invariant; kept as defence-in-depth, but its test now says so rather than implying the state is reachable.
- [ ] 10.11 **Accepted, not fixed — no test pins the stat-before-read ordering.** Design D2 argues the ordering is load-bearing (the reverse produces a false "just now", the failure a reader acts on), but all three service tests stamp a static file and pass either way, and `cargo mutants` generates value and operator mutants, not statement reorderings. Testing it honestly would need a write interleaved between the two syscalls — inherently racy, and a flaky test here would be worse than none. Recorded as a known gap: the guarantee rests on the code comment and D2, not on the suite.

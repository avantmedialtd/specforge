# Add a seasonal battle pass with procedural badge treatments

## Why

The gamified profile we just shipped has a **terminal-progression** problem, and it is the one the user named: milestones are hard to author and easy to exhaust. The board fills, every badge goes gold, and the game quietly ends — exactly when a returning developer should feel pulled back in. Worse, a *cumulative* badge wall is the opposite of motivating for a veteran: every counter only ever rises, so there is no fresh climb, no underdog feeling, no reason to show up *this* month rather than last.

A **season** system fixes both halves with two separate levers. **Regeneration** — goals and rewards are *produced*, not hand-authored — kills the content treadmill. **Reset** — the seasonal climb restarts each month from zero — kills terminal progression and manufactures the underdog feeling on a recurring cadence. The crucial constraint for *this* app is that progress here is **real shipped work**: you cannot honestly zero someone's lifetime ships. So the season resets *standings* (a score, a tier ladder, a fresh objective set), never *facts*. Lifetime work, the streak, and earned milestones stay permanent — a second, never-demoting track that preserves identity while the seasonal track restarts the dopamine.

Two facts about the existing substrate make the "biggest build" tractable. First, the **activity log is already authored, timestamped, and git-backfilled**, so a season's score and objective progress are a *pure projection* of data we already have — they inherit append-only correctness, backfill, Me/Everyone scope, and watcher reactivity for free, with no new event kinds. Second, the **identicon already proves the procedural pattern**: `identity.rs` generates an avatar deterministically from a key, tinted from the token palette, locally, with no network. Battle-pass rewards reuse exactly that pattern — a reward is a function of `(season, tier)`, so an endless stream of distinct collectibles costs zero authoring.

## What Changes

- **A monthly season model (`seasons`).** Calendar-month seasons in the viewer's local time zone (consistent with the commit-graph rail's day grouping), each with a deterministic generated name (an adjective+noun derived from the season index, à la the identicon — flavor without per-season copywriting).
- **A two-track progression (`seasons`).** A **seasonal** track — a season score that resets to zero each month and drives a **battle-pass tier ladder**, with fine tiers grouped into named bands so one number reads two ways (`tier 14 → 15` *and* `Gold II`). And a **career** track — a permanent tier derived from the existing lifetime cumulative totals that **only ever rises and never demotes**. The **streak survives the season boundary** (it is a career line; resetting it would punish a developer for the calendar).
- **A weighted season-score economy (`seasons`).** Season score accumulates from the existing authored achievements within the season window, Me-scope-resolved — a ship counts most, then objective completions, artifacts, tasks, active-day streak credit, and commits. Score is *derived*; no new event kinds are recorded.
- **Adaptive + overflow pacing (`seasons`).** Tier thresholds scale gently to the developer's trailing baseline (reusing the recent-daily-average the Today's-Progress comparison already computes) so the ladder is always a stretch rather than a wall or a week-one walkover, with an **overflow lane** past the final tier so a prolific month is never wasted.
- **Rotating seasonal objectives (`seasons`).** ~7 objective **archetypes** (volume, cadence, streak, burst, breadth, full-lifecycle finish, comeback) × adaptive thresholds × per-season rotation, all derivable from existing event kinds. Completing an objective grants bonus season score. This is the engine that makes "hard to come up with new ones" a non-problem: effectively endless objectives, authored once as templates.
- **Procedural badge treatments as the battle-pass unlock (`seasons`).** Each tier unlocks a **rendering treatment** (a holographic / animated / season-tinted finish) seeded deterministically by `(season index, tier index)` and applied to the developer's **earned milestone badges**. Treatments are applied *to* badges (not one skin per badge, which would run out), so the badge system deepens rather than sprawls. Higher tiers yield rarer treatments. Generation is local, deterministic, token-palette-based — no network, no art authoring, distinct every season.
- **A treatment locker with soft-FOMO (`seasons`).** Unlocked treatments are kept **permanently** in a locker and can be **equipped** onto badges. A season's treatments are limited-time, but a subset **rotates back via a vault** so a missed season is never permanently punishing — appropriate for a productivity tool, where a slow month (vacation, sickness, non-OpenSpec work) must not feel like a penalty. The locker + equipped selection is the **only genuinely new persisted state**.
- **Season rollover and an auto-minted recap (`seasons`).** At the month boundary the system mints a **recap** synthesised from the activity log (shipped, best streak, band reached, objectives completed, treatments unlocked — a "Wrapped" moment that writes itself), locks in any career-tier promotion, **keeps** the locker, streak, and lifetime stats, **resets** score/band/objectives/track, and rolls a fresh season name + objective set + treatment seed. **Backfilled past seasons are silent** historical recaps that trigger no live celebration (inheriting the existing backfilled-milestone-silence rule).
- **A season home on the dashboard profile band (`dashboard`).** The profile band gains the live season surface — name, countdown, current band/tier with gap-to-next, the track strip with the next unlock preview, active objectives, the equipped treatment wrapping the avatar/badges — alongside the permanent career tier rendered distinctly.
- **A This-Season / All-Time lens (`dashboard`).** Reusing the existing Me/Everyone scope-control pattern, a second lens filters the today/streak/heatmap/milestone views to the active season or to all time.
- **A seasonal leaderboard twin for shared repositories (`dashboard`).** The existing per-author leaderboard gains a season-scoped variant so teammates re-climb from zero together each month; the all-time leaderboard remains. Both stay read-only and local, and omit for solo history.

## Capabilities

### New Capabilities

- `seasons`: the monthly season model and deterministic naming; the two-track design (resetting seasonal ladder + permanent career tier) and the rule that the streak survives a boundary; the weighted season-score economy derived from the authored activity log; adaptive + overflow tier pacing; the rotating objective archetypes; the deterministic `(season, tier)` badge-treatment generator; the treatment locker, equipped selection, soft-FOMO vault, and app-data persistence that never writes a workspace; season rollover, the auto-minted recap, and silent backfilled past seasons.

### Modified Capabilities

- `dashboard`: a new *Season Home* surface on the profile band (name, countdown, band/tier + gap-to-next, track strip, objectives, equipped treatment) and a permanent *Career Tier* readout rendered distinctly from the seasonal one; a *This-Season / All-Time* lens over the existing today/streak/heatmap/milestone views; a season-scoped variant of the *Per-Author Leaderboard*; a live tier-up acknowledgement consistent with the existing celebration rules and reduced-motion handling. The read-only invariant is unchanged.
- `activity-log`: the *Bounded, Time-Bucketed Queries* requirement is extended to support **calendar-month (season) windows**, Me-scope-resolved, sufficient to derive a season's weighted score and objective progress. This is additive — **no new event kinds are recorded**; season standings are derivations over the existing authored, append-only log.

The `developer-identity` capability is **reused unchanged**: treatments key off `(season, tier)` rather than identity, and the locker is implicitly the local developer's (Me scope), so no identity requirement changes.

## Impact

- **Specs:** one new capability (`seasons`); two modified (`dashboard`, `activity-log`).
- **Code:**
  - `crates/openspec-core/src/seasons.rs` *(new)* — calendar-month windowing (local TZ); the weighted season-score economy over the Me-scope-resolved activity log; the band/tier ladder with adaptive thresholds (reusing the trailing-average baseline) and the overflow lane; the rotating objective generator (archetypes × adaptive thresholds × per-season rotation); the deterministic badge-treatment generator seeded by `(season index, tier index)` and tinted from the token palette; deterministic season naming; recap synthesis; and the permanent career-tier derivation from cumulative totals.
  - `crates/openspec-core/src/activity_log.rs` — season-window query helpers (month-bucketed, Me-scope-resolved); no schema change to `Achievement`.
  - `crates/openspec-core/src/dashboard.rs` — fold season state into the dashboard payload; the This-Season/All-Time lens over the existing aggregations; the seasonal leaderboard twin; a tier-up live-moment hook.
  - `crates/openspec-core/src/identity.rs` — reused unchanged (the procedural-generation precedent).
  - `crates/specforge/src/settings.rs` — persist the treatment **locker** (unlocked treatments) and the **equipped** selection alongside `AppSettings`, in the app data directory; serde defaults so an absent locker loads empty.
  - `crates/specforge/src/commands.rs` — `get_season` (current season state + objectives + track), `set_equipped_treatment`, and recap access; `get_dashboard` gains the This-Season/All-Time lens.
  - `crates/openspec-core/src/lib.rs`, `crates/specforge/src/lib.rs` — wiring, re-exports, and rollover detection (at launch and when crossing a month boundary while running).
  - Frontend: `src/types.ts` (season, band/tier, objective, treatment, locker, recap, lens mirrors), `src/api.ts`, `src/hooks/useDashboard.ts`, `src/components/DashboardView.tsx` (season home on the profile band, track strip, objectives, equipped treatments on the avatar and badges, recap card, This-Season/All-Time toggle), `src/App.css`.
- **Behaviour delta:** the profile band gains a live season home and a permanent career tier; earned milestone badges can wear collected treatments; a This-Season/All-Time lens filters the existing gamified views; shared repos gain a season-scoped leaderboard twin. Solo personal repos look the same plus the new season surfaces. No workspace files are written; no network calls are made.
- **Risk:** moderate but contained. Season score, objectives, and recaps are pure derivations of the existing authored, append-only log — no migration, no new event kinds. The only new persisted state (the treatment locker + equipped selection) is additive in app-data. The chief *tone* risk — a slow month feeling like a punishment — is mitigated by design: adaptive thresholds lower the bar after a quiet stretch, the Comeback objective rewards returning, soft-FOMO keeps earned treatments forever with a rotating vault for missed ones, and the career tier never demotes. Backfilled past seasons are silent, so first launch does not spam celebrations.

## Out of Scope

- **New cosmetic categories beyond badge treatments.** Avatar frames, profile palettes, and equippable titles were considered and deliberately deferred; the locker is badge-treatments-only this change.
- **Hard / permanently-missable FOMO.** Soft FOMO only — earned treatments are kept forever and missed ones can return via the vault. No reward is permanently lost to a calendar gap.
- **Configurable season cadence.** Monthly only this change; weekly/quarterly seasons are a possible later setting.
- **Network or paid content.** No fetched cosmetics, no Gravatar, no CDN, no premium/paid pass, no boosts. Season score comes only from real recorded activity.
- **Cross-machine or multiplayer season sync.** No account, no server; the leaderboard is bounded to a repository's own git authorship, as today.
- **Rewriting or re-attributing the activity log.** Seasons are read-only derivations; the log stays append-only and authored exactly as it is recorded.
- **Audio.** No sound on tier-ups or rollover.

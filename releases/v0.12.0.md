SpecForge v0.12.0

Every markdown file in your workspace is now reachable — plus a tree that shows completion at a glance.

## ✨ Highlights

- **Browse all the markdown in a workspace, not just its OpenSpec artifacts.** Clicking a repository row or a flat workspace row used to do nothing — the click was reserved for "later UX work". It now opens a read-only file browser in the content area: a folder tree of every markdown file in that workspace on the left, the selected file rendered on the right with the same viewer used for proposals and specs. READMEs, docs, design notes, scratch files — anything `.md` — are one click away. For git repositories the list comes from git's own index (`git ls-files`), so `.gitignore` is respected for free, ignored trees like `node_modules/` and `target/` are never even visited, untracked drafts still show up, and WSL workspaces enumerate inside the VM instead of stat-ing over the 9P share. Folders with no markdown anywhere beneath them simply don't appear, expanding a folder costs no round trip, and the commit rail keeps re-scoping to the clicked repository exactly as before. Reads are confined to the workspace root and to `.md` files, and the list refreshes when you open it rather than through a new file watcher. Available in the web UI as well.

## 🔧 Improvements

- **Completed changes are now highlighted, not just marked.** A change with every task done gets a soft green wash across the whole row, on top of the green left rail and the filled completion disc it already had — so "done" is something the eye lands on rather than a thin edge and a small glyph. Hovering deepens the wash. Selection still wins: a selected row shows the usual accent highlight, and the completion disc stays put, so colour is never the only thing carrying the meaning.

- **Task checkboxes in rendered markdown are drawn by the app.** `tasks.md` was still showing washed-out, undersized native OS checkboxes — the last raw control in the content area. They are now custom glyphs sized flush with the body text: a done task gets a solid green square with the check knocked out (the squared-off sibling of the tree's completion mark) and its line text dims, while a pending task gets a quiet outlined box. The result is that unfinished work jumps out when you scan a task list. The glyphs stay inert and still announce their checked/unchecked state to assistive technology; the settings toggle, which is a real control, is unchanged.

## 🩹 Fixes

- **Faint text in light mode now clears the AA contrast floor.** The light-scheme faint-ink token was measuring below the 4.5:1 ratio the palette requirement already mandated. It has been darkened, which lifts every muted label, secondary line, and dimmed task in light appearance.

### Downloads

- **macOS** — `SpecForge_0.12.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.12.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.12.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.12.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.12.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.12.0_windows-x64.zip`.

SpecForge v0.14.0

The headless web server stops being a source-only curiosity: it ships as a download, and it can now serve your workspaces to the rest of your network.

## ✨ Highlights

- **`specforge-serve` is now a standalone download.** SpecForge has been able to serve its browser skin — the same dashboard, spec browser, and live-updating change tree the desktop app renders — from a headless server for a while. The catch was that the release never actually built it, so the only way to run it was to clone the repo, install a Rust toolchain, and build it yourself. It now ships as an archive for macOS (universal), Linux x64, and Windows x64, right beside the terminal client. Extract it, run it, open a browser: no GUI, no WebView, no desktop session required on the machine doing the serving.

- **`--bind` publishes the web UI on your network.** Until now the server bound `127.0.0.1` and nothing else, so viewing it from a second machine meant an SSH tunnel or a `tailscale serve` proxy. `specforge-serve --bind 0.0.0.0 --port 4317` publishes it directly — open `http://<host-ip>:4317` from a laptop, tablet, or phone on the same network and browse the workspaces registered on that box, with the change tree live-updating over SSE exactly as it does locally. Loopback remains the default, and a network bind can only ever come from the command line (or `SPECFORGE_WEB_BIND`) on that specific invocation — there is no stored setting that turns it on, and the desktop app's own serve toggle is untouched and stays loopback-only.

  **A network bind is unauthenticated — treat it as a trusted-network feature.** Everyone who can reach the port can read every `.md` in every registered workspace and browse your commit history and diffs, with no login. It also means the browser origin check has to stand aside, so a malicious website visited by *any* browser on that network can read the same data without being on the network itself. The server says so at startup when you bind a non-loopback address. On a home or lab network that you control, this is the point of the feature; on anything shared or untrusted, `tailscale serve` and SSH tunnels are still the right tools and work exactly as before. Nothing here can write to your files or run anything on the serving machine — the surface is read and app-settings only.

- **A network bind refuses to start rather than quietly weakening Tailscale access control.** If you have a Tailscale login allow-list configured, that restriction relies on the server being loopback-bound — otherwise anyone reaching the port could simply supply the identity header themselves. Combining the two now fails loudly at startup, naming both, instead of starting up with a restriction you believe is in force but isn't.

## 🔧 Improvements

- `specforge-serve` gained `--help` and `--version`. It's a binary you now download onto remote machines, where `--help` is the only documentation within reach.
- `SPECFORGE_WEB_BIND` joins the existing `SPECFORGE_WEB_PORT` as an environment fallback, for service files and containers.
- A malformed `--bind` value exits with an error naming it, rather than silently falling back to loopback and leaving you wondering why the server isn't reachable.

### Downloads

- **macOS** — `SpecForge_0.14.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.14.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.14.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.14.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.14.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.14.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server, one archive per platform — extract and run
`./specforge-serve`. It binds `127.0.0.1:4317` by default; `--bind 0.0.0.0` (or
any other interface address) publishes it on the network, **unauthenticated**
— only do this on a network you trust:

- **macOS** — `specforge-serve_0.14.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`.
- **Linux** — `specforge-serve_0.14.0_linux-x64.tar.gz`.
- **Windows** — `specforge-serve_0.14.0_windows-x64.zip`.

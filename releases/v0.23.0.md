SpecForge v0.23.0

SpecForge stops showing you one worktree and calling it the repository. The
Archive and the file browser both pool across every worktree a repository has,
and the Dashboard loses the band that was saying what the rest of it already
said.

## ✨ Highlights

- **The Archive spans every worktree of a repository.** The Archive browser
  built its dropdown from user-registered folders only, so every worktree
  SpecForge discovers on its own — including every `.claude/worktrees/*` a
  feature branch creates — was simply unreachable, and a change archived inside
  its own worktree was invisible until that worktree was registered as its own
  top-level row. The view is now scoped to the **repository**: one listing
  fanned out across every tracked worktree, registered and discovered alike,
  de-duplicated on the change's logical id rather than its dated directory name,
  so the same change archived on two different days collapses into one row
  instead of two. When a change really does exist in more than one worktree, the
  opened reader gains a copy selector that re-points just that reader at another
  copy; when it exists in one, which is almost always, it is a plain label.
  Copies are named by workspace, never by branch — the worktree a change was
  archived in is routinely not the branch the change belongs to.
- **The file browser spans them too.** Clicking a Repo group rooted the browser
  at the repository's main worktree, so a design note written this morning in a
  feature worktree, or any draft that had never been committed, could not be
  read at all. The browse root is now the repository: every tracked worktree is
  enumerated and the results pooled into one tree, de-duplicated on the path
  relative to each root, with untracked-but-not-ignored files still included per
  worktree. Because every worktree sits on a different branch, copies of a file
  usually *disagree* — so the tree marks the rows whose copies differ, which
  tells you exactly where your branches have drifted. Opening a file gives you
  the same per-file copy selector, and a relative link inside a preview resolves
  within the copy you are actually reading rather than leaking into another
  worktree.
- **A shorter Dashboard.** The Overview band is gone. Its per-repository
  breakdown decomposed two totals the Dashboard already prints in its footnote,
  and answered "which repository holds my work" — a question the workspace tree
  answers continuously, and without a five-row cap. The commit garden directly
  below is now the only per-repository surface, and it keeps the one piece worth
  keeping: each plot caption carries that entry's active-change count. On a busy
  day this saves a section heading, a divider rule, a panel heading and five
  rows; on a quiet day the garden simply omits itself and all of it goes.

## 🔧 Improvements

- **The commit garden's plots hold a stable order.** They rendered in registry
  order with no tiebreak, so two plots could trade places between refreshes — a
  flaw masked while they sat beneath a rigorously sorted neighbour. They are now
  ordered by today's commit count descending, then label, then a stable key, so
  entries sharing a display label no longer fall back to registration order or
  remount the plots below them on a rank change.
- **A guard against a whole class of IPC bug.** A test now serializes the types
  the interface actually reads, walks the resulting JSON recursively, and fails
  the build on any key that is not camelCase. It observes what is really emitted
  rather than reading the source, so it catches the mistake in types that do not
  exist yet — including the one below, which had already shipped twice.

## 🗑 Removed

- **The Dashboard's Overview analytics band**, with its per-repository
  breakdown, its proportional bars, its five-row cap and remainder line, and the
  windowed lifecycle figures printed on its divider rule (changes archived in
  the last fourteen days, and mean time to archive). The lifecycle *mining*
  behind those figures is untouched — it still dates every entry in today's
  ships feed.

## 🩹 Fixes

- **Renaming a flat (non-git) workspace now actually applies.** The new name
  saved and the Settings row echoed it back, while the tree row, the window
  label, the file-browser header and the reader title all kept showing the
  folder basename — and the tint set in the very same dialog *did* apply, so it
  read as flakiness rather than a bug. A flat workspace's name was going out
  over the wire under a key the interface does not read; it now matches
  everywhere.
- **Clicking a ship on the Dashboard opens the right change.** When a change was
  archived in a discovered worktree, the deep link resolved to the repository's
  main worktree, whose archive does not contain it, and the selection was
  silently dropped. The change is now in the listing whatever worktree holds it.
- **The `[stale]` divergence label fires against real archives.** Active changes
  were keyed on the bare change id and archived ones on the dated directory
  name, so the two could never match and the label could not be produced for any
  archive directory that carries a date — which is all of them in practice.
- **A change that is archived in one worktree and active in another is counted
  as both.** Re-keying on the logical id briefly made such a change one entry
  with a mixed set, sending title-less directory stubs to every frontend and the
  terminal client; the two flavours are now partitioned, so the change appears
  under one name in both sections with its counts intact.
- **Mathematics in archived specs renders as mathematics.** 122 single-dollar
  spans across 19 archived changes displayed as literal text in the spec
  browser, because the authoring guidance said single-dollar was inline maths
  while the reader deliberately does the opposite, so that prose about a $50
  licence is never silently re-typeset. The guidance is corrected, the spec it
  had already broken is fixed, and the archive's notation now sets in line where
  it sits.

### Downloads

- **macOS** — `SpecForge_0.23.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.23.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.23.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.23.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.23.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.23.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server. The quickest way to run it is npm — no download, and
**no quarantine step**, because npm installs are not flagged the way browser
downloads are:

```bash
npx @avantmedia/specforge          # or: npm install -g @avantmedia/specforge
```

Only your platform's binary is fetched. It binds `127.0.0.1:4317` by default;
`--bind 0.0.0.0` (or any other interface address) publishes it on the network,
**unauthenticated** — only do this on a network you trust.

Prefer a direct download? One archive per platform — extract and run
`./specforge-serve`:

- **macOS** — `specforge-serve_0.23.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`. (This does not apply to
  the npm install above.)
- **Linux** — `specforge-serve_0.23.0_linux-x64.tar.gz` or
  `specforge-serve_0.23.0_linux-arm64.tar.gz`. Statically linked against
  musl, so one binary covers Alpine and containers as well as current and
  older glibc distributions.
- **Windows** — `specforge-serve_0.23.0_windows-x64.zip`.

SpecForge v0.24.0

The sidebar stops being a five-level tree. It now lists workspaces and changes
and nothing beneath them; everything that used to live under a change — which
artifact you are reading, which worktree you are reading it in, where you are
inside the document — moves to the header and to a new outline beside the prose.

## ✨ Highlights

- **A two-level sidebar.** The tree used to unfold every change into its
  artifacts, each spec, each section and each task, so one change routinely
  took eleven rows before its neighbour came into view. It now stops at the
  change row. Every mark the row carried survives — title and directory name,
  branch chip, progress meter, modification time, working-tree status,
  favourite toggle, completion glyph — and clicking a change opens its first
  present artifact straight away. A change that lives in several worktrees is
  a single row with a worktree count instead of a disclosure group, and the
  keyboard model shrinks to match: arrows across rows, Left and Right to open
  or close a workspace, Home, End and first-letter typeahead.
- **Artifact tabs in the change header.** Below the identity line the detail
  pane now offers Proposal, Design, Tasks and one tab per capability spec —
  only the ones that exist on disk, exactly as the Archive reader has always
  done. The Tasks tab carries the progress meter the old Tasks node showed,
  and the strip is a proper tab list: Left and Right move, Enter activates.
  Selecting a tab is a real navigation, so history, deep links and reader
  windows behave exactly as a tree click did.
- **An instance switcher for changes in more than one worktree.** When a
  change is checked out in several worktrees the header shows one button per
  worktree, each with its branch chip and divergence label, and switching
  re-points the pane at that copy. This is the Archive's copy-selection model
  applied to live changes.
- **A document outline.** Every reading surface — the detail pane, the file
  browser's preview and reader windows — gains an outline built from the
  document's headings, seated beside the prose column and hidden when the
  pane has no room beside it (the `full` reading-width setting never shows
  it). Activating an entry scrolls to that heading without touching history;
  the current section is marked as you scroll. For a tasks document each
  entry shows its section's done count, so the per-section progress the tree
  used to show is still one glance away.
- **Fragment links now work.** A `#heading` link inside a rendered artifact
  used to be inert, reserved for future navigation. It now scrolls to the
  matching heading within the document; a fragment with no matching heading
  gets the same dangling-link treatment as a broken path.

## 🔧 Improvements

- **The Archive reader shares the live header.** It used to stack its own
  header, copy row and tab strip above the pane's identity line. It now
  renders the same change header in a read-only form: a back control, the
  archive date and title in the leading row, the copy selector where the
  instance switcher stands, and tabs from the copy's artifacts — with no
  branch chip, as before. On macOS the archived change's name now clears the
  titlebar drag region like the live header does, so a click copies it and a
  double-click no longer zooms the window.

## 🗑 Removed

- **Jumping to a single task line from the sidebar.** Task lines are reached
  by scrolling within their section from the outline instead.
- **Persisted tree collapse state.** With only two levels there is nothing
  worth remembering between sessions; workspace rows open by default and
  their state lasts for the session. Existing stored collapse sets are
  ignored, not migrated.

### Downloads

- **macOS** — `SpecForge_0.24.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.24.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.24.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.24.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.24.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.24.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server. The quickest way to run it is npm — no download, and
**no quarantine step**, because npm installs are not flagged the way browser
downloads are:

```bash
npx @avantmedia/specforge          # or: npm install -g @avantmedia/specforge
```

Only your platform's binary is fetched. It binds `127.0.0.1:4317` by default;
`--bind 0.0.0.0` (or any other interface address) publishes it on the network,
**unauthenticated** — only do this on a network you trust.

Prefer a direct download? One archive per platform — extract and run
`./specforge-serve`:

- **macOS** — `specforge-serve_0.24.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`. (This does not apply to
  the npm install above.)
- **Linux** — `specforge-serve_0.24.0_linux-x64.tar.gz` or
  `specforge-serve_0.24.0_linux-arm64.tar.gz`. Statically linked against
  musl, so one binary covers Alpine and containers as well as current and
  older glibc distributions.
- **Windows** — `specforge-serve_0.24.0_windows-x64.zip`.

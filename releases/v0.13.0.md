SpecForge v0.13.0

Artifacts now render most of what authors actually put in them — math, hand-written SVG, working links — and the app stops stalling while it does it.

## ✨ Highlights

- **Mathematical notation renders.** Complexity bounds, formulas, and invariants written for GitHub now render here the same way, via KaTeX: inline `$…$`, display `$$…$$`, and ```` ```math ```` fences. Invalid LaTeX degrades quietly — the expression shows its own source in place with an error indication while the rest of the artifact renders normally — and math follows the active colour scheme with no extra theming. KaTeX and its fonts are bundled locally rather than pulled from a CDN, so this works offline, and the fonts only fetch when a document actually contains math. Rendering runs with KaTeX's non-trusting posture, so LaTeX that would emit active content (`\href` and friends) produces no live links or scripts.

- **`svg` code fences render as pictures.** Agents and authors were limited to mermaid for diagrams; a raw SVG block was silently dropped and an `svg` fence showed up as highlighted source. It now renders as an image, following the same interception the mermaid fence uses — so a design doc can embed precise layouts, custom geometry, and annotated mockups that mermaid cannot express, self-contained in the markdown with no side files to break when the change is archived. A rewrite pass makes naïve fences just work: a missing `xmlns` is injected, missing `width`/`height` are derived from the `viewBox`, and the live text token is injected as the root `color` so `currentColor` diagrams follow light and dark mode. The SVG becomes a data-URI `<img>`, which makes scripts, event handlers, and external fetches inside fence content structurally unable to execute — the same posture as mermaid, without adding a sanitizer. Invalid SVG falls back to the raw source with a quiet note; every other fence, `xml` included, is untouched.

- **Links in artifacts do something useful instead of hijacking the app.** Clicking any link in a rendered artifact used to navigate the entire window away from the app UI — a stray URL in a proposal took SpecForge with it. Every link activation is now intercepted and dispatched by class: `http(s)` links open in your system browser, `mailto:`/`tel:` go to the OS handler, and relative file links resolve against the file you are viewing and open through the OS default handler. That last one makes HTML mockups a first-class attachment — `[login mockup](./mockups/login.html)` is now one click, and because the real browser opens it, the mockup's sibling stylesheets, scripts, and images resolve for free. Opening is confined to the authorized workspace root and to document types (`.html`, images, `.css`, `.pdf`, `.txt`, `.json`, `.csv`); executables, scripts, and directories are refused, so a link can never run a file. A shell-side navigation guard backstops the routes a DOM handler cannot see, such as the context menu's open-link action and link drag-out. Links that are deliberately inert — relative markdown links, bare fragments, `javascript:`/`file:`/`data:` — now say so visibly rather than appearing broken. In the web UI external links open in an opener-isolated tab and file links degrade to showing their path; the terminal UI shows each link's destination and never spawns an opener.

- **A ChatGPT quota gauge, beside the Claude one.** If your day is split between Claude Code and the Codex CLI, the ChatGPT side was invisible until Codex started refusing work mid-session. An opt-in gauge (default **off**) now reports your plan's 5-hour and weekly window usage in the sidebar footer and the TUI title bar, using the same green / orange / red thresholds, exhausted-window reset countdown, and stale de-emphasis as the Claude gauge. It reads the Codex CLI's existing token file read-only (honouring `CODEX_HOME`), rejects expired tokens locally without a round trip, and — because ChatGPT's response carries each window's length — draws its time axis from the server-provided window rather than a hardcoded guess. Enable it in Settings, next to the Claude quota row.

- **Editing, committing, and archiving no longer stall the app.** Every file save under `openspec/changes/` triggered a full cross-repository git sweep: on a 12-repository / 17-worktree registry that was 46 sequential git processes taking 576 ms, run on a runtime worker thread with both the registry lock and the cache lock held for the whole duration — so a save in one repository blocked everything, including work in unrelated repositories. That path is now scoped to the repository you actually edited, gathers its inputs and releases both locks *before* any git runs, moves off the async runtime, issues the per-worktree calls concurrently (the same calls measured at 179 ms against the 576 ms serial baseline), merges two git spawns into one `git status --porcelain=v2 --branch`, and memoizes the local git identity. A batch that adds N worktrees now performs one sweep instead of N, and the frontend collapses the several events one debounced batch legitimately emits into a single refetch instead of refetching per event.

- **The Dashboard stops re-reading your entire git history on every open.** Change-lifecycle mining walked each repository's full history with no `--since` and no `--max-count`, once per registered repository per fetch — 482 ms on a quiet machine and 983 ms under load across 12 repositories, roughly three-quarters of the Dashboard's total git cost, growing without limit as repositories age. Since a change's creation and archival commits are append-only history, the result is now cached per repository and dropped only when that repository's refs actually move, using the graph-change signal the app already emits — so reopening the Dashboard with no commits in between mines nothing, and committing in one repository re-mines only that one. Concurrent fetches for a cold repository share a single mining pass rather than each spawning their own, and failures are never cached, so a transient git error can't pin an empty lifecycle for the rest of the session.

## 🔧 Improvements

- **The test suite is now gated on whether it would actually catch a bug.** A green suite proves the tests *run*; it says nothing about whether they would notice a regression. `cargo-mutants` now injects small behavioural bugs into the headless crates and reports which ones no test catches, and CI fails a push when a line it changed has no test defending it. Existing survivors are treated as a backlog rather than a wall.

- **A macOS-only test failure that had been red locally while passing on CI is fixed.** The concurrency test proving a cache write isn't blocked by an in-flight recompute asserted its invariant by racing two operations and hoping the ordering held. On Apple Silicon the ordering inverted. It now parks the recompute at a deterministic rendezvous point, so the assertion has no timing component at all — the same discipline the repo prefers over widening a margin.

## 🩹 Fixes

- **Mermaid diagrams are readable in dark mode.** `erDiagram` attribute rows rendered near-white behind near-white text, because the app mapped its design tokens onto mermaid's base theme without telling it the palette was dark — so every colour mermaid *derives* rather than receives was computed as if lightening a light theme. The active scheme is now passed through, so derived colours move in the right direction, and the ER row fills are mapped onto design tokens explicitly instead of trusting the engine's lighten/darken math.

### Downloads

- **macOS** — `SpecForge_0.13.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.13.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.13.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

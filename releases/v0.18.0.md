SpecForge v0.18.0

The served web UI stops being a page and becomes an app you can install.

## ✨ Highlights

- **The served UI installs to a phone or tablet home screen, with its own icon and its own window.** `tailscale serve` has been able to publish the web UI over real HTTPS to exactly those devices for a while, and `touch-input` already treats them as a designed-for surface — but there was nothing to install. The bundle now ships a web app manifest with `display: standalone`, so iOS **Add to Home Screen** produces a real app entry: SpecForge's own icon on the springboard, a window with no browser chrome, and a dark launch screen instead of a white flash.

  The manifest's `start_url` is **relative**, which is what makes one build correct everywhere it is served from. An absolute start URL would bake in whichever origin the author happened to be using and silently mis-scope the install on every other — precisely the tailnet case this exists for. The same bundle now installs correctly on `127.0.0.1:<port>`, on any port `SPECFORGE_WEB_PORT` selects, and on a `*.ts.net` name.

- **Every tab shows a SpecForge mark, and it is legible at 16 px.** The served UI carried no icon markup at all, so every tab rendered the browser's generic page glyph. The fix is a **two-source** icon set rather than one image downscaled to death: the canonical 1024×1024 forge illustration is a painterly scene with a stone frame, an anvil, a hammer and sparks — at 32 px it is muddy but readable, and at 16 px it collapses to a gold smear.

  So the small sizes come from a hand-authored flat anvil glyph, and 180 px and up are rasterizations of the canonical illustration. Android installers also get a separate **maskable** icon in which the illustration is inset on a solid field — declaring the full-bleed square as maskable would let a circular mask slice the stone frame's corners off, and shipping none at all produces a visible frame-within-a-frame where the installer composites its own backdrop.

- **An installed app the OS suspended comes back live, not silently stale.** In a long-lived browser tab this never mattered: the tab stays alive and `EventSource` retries transient drops itself. An installed standalone app is different — iOS suspends the whole document, and it can come back with the stream in `CLOSED`, where nothing will ever retry it. The UI would keep rendering pre-suspension state while looking perfectly live.

  On the document being restored, the client now checks the stream and, if it is no longer open, replaces it **and re-reads current state**. The refetch is not optional: the server sets no event ids and keeps no history — a lagging receiver is deliberately skipped rather than replayed — so a reconnected client has no way to learn what it missed, and reconnecting alone would sit on stale data until some unrelated event happened to arrive. A healthy stream is never touched, so ordinary tab switching stays free, and overlapping resumes collapse into a single read.

## 🔧 Improvements

- **The icon set is regenerable, and the authored glyph is protected from regeneration.** `bun run icons:web` rebuilds the raster sizes from the canonical 1024×1024 source and the `.ico` from the authored glyph. `product-identity` now names the web set as a second, separately-generated family of derivatives from that same source, and records the authored anvil glyph as a non-derivative authored mark — the same protection the two tray SVGs already have, so a future regeneration run cannot mistake either for output to overwrite. The tray glyphs and the native `bun tauri icon` bundle icons are untouched.
- **Browser chrome takes the product's own colours.** A pair of `theme-color` meta tags discriminated by `prefers-color-scheme` read the light and dark `--bg` tokens the visual identity already defines, rather than fresh hand-picked literals. The manifest holds only one value and uses the dark one, so the pre-boot launch screen matches the field the icon sits on.
- **No service worker, deliberately.** Offline support for a UI whose entire content comes from a live local server would be a stale-shell failure mode rather than a feature, and iOS home-screen install does not require one. The cost is that Android's install prompt stays unavailable.
- Builds stay clean on Rust 1.98, where the tray rasterizer's chunking helper picked up a new lint.

## 🩹 Fixes

- **A request for an icon is no longer answered with an HTML document.** The web server falls back to the app shell for unmatched paths so client-side deep links survive a reload — correct for routes and wrong for assets, which meant the browser's unprompted `GET /favicon.ico` received `200 text/html` and the whole of `index.html`. An answer that is not merely missing but actively wrong.

  Requests inside the bundle's own static-asset namespace — the generated `assets/` directory, the well-known root files, and root-level icon rasters including the `apple-touch-icon*` variants older iOS probes on its own — now answer an honest `404` when the file is absent. The boundary is an **explicit allowlist, not a test for a file extension**: deep links are built from workspace and change identifiers that may legitimately contain dots, so an extension heuristic would have turned a working link into a `404` the first time somebody named a change `v1.2`.

### Downloads

- **macOS** — `SpecForge_0.18.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.18.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.18.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.18.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.18.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.18.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server, one archive per platform — extract and run
`./specforge-serve`. It binds `127.0.0.1:4317` by default; `--bind 0.0.0.0` (or
any other interface address) publishes it on the network, **unauthenticated**
— only do this on a network you trust:

- **macOS** — `specforge-serve_0.18.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`.
- **Linux** — `specforge-serve_0.18.0_linux-x64.tar.gz`.
- **Windows** — `specforge-serve_0.18.0_windows-x64.zip`.

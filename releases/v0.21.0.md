SpecForge v0.21.0

Documents get their own windows, stay live wherever they sit in the workspace,
and finally render the way they read.

## ⚠️ Breaking

- **Single-dollar `$…$` is no longer inline math.** `$$…$$` (which is already
  inline when embedded in prose) and ```` ```math ```` fences are now the only
  math delimiters. The old behaviour silently ate ordinary prose — "costs $50
  per seat and $60 for the next" became a formula — which is a worse failure
  than needing two dollar signs, because nothing tells you it happened. If your
  documents use `$…$` for real formulas, change those to `$$…$$`; the migration
  is mechanical, and prose containing dollar amounts now renders as written.

## ✨ Highlights

- **Open any document in its own window.** A reader window carries the rendered
  document and its identity header and nothing else — no tree, no commit rail,
  no footer, no quota pills. Park a capability spec on a second monitor, compare
  two specs side by side, or keep one visible while you work in another
  application. Cmd/Ctrl-click a row to open that row's document, or use the
  control in the header of whatever you are already reading — a visible control,
  not just a modifier chord, so the feature is reachable on a touch device and
  discoverable without hovering. Dismiss with Cmd/Ctrl-W, Escape, or the window's
  own close control; opening the same document twice focuses the window you
  already have rather than stacking a second one.
- **Documents stay fresh wherever they live.** Until now only artifacts under
  `openspec/changes/` updated live — `openspec/specs/<capability>/spec.md`, the
  file most people would actually call *the spec*, was a snapshot, and so was
  every file in the file browser's preview. A new per-document filesystem watch
  keeps every document surface current: the detail pane, the reader window, and
  the file-browser preview all update in place as the file is rewritten under
  them by an agent, an editor, or a `git checkout` — without disturbing your
  scroll position. The watch follows the parent directory rather than the file,
  so a save-by-atomic-rename from a normal editor doesn't quietly sever it.
- **Markdown files are addressable.** `/w/<workspace>/file/<path…>` and
  `/r/<repo>/file/<path…>` name a single file beneath a browse root, so a
  document can be linked, bookmarked, deep-linked, and handed to a window. In
  the browser build a reader's URL is shareable and reopens the same reader.
- **Formulas, tables, and diagrams read properly.** Display math no longer clips
  its own summation limits and subscripts against its scroll container, and no
  longer grows spurious scrollbars; inline math is sized to sit with the prose
  around it instead of 21% larger. Wide tables scroll inside their own block
  instead of overhanging the column, with a distinct header surface and denser
  cell text. A mermaid diagram that would have to shrink its labels below legible
  size stops shrinking and scrolls horizontally instead — and when a figure is
  displayed below its natural size, the maximize control is visible at rest
  rather than waiting for a hover.
- **Code is readable in light mode.** The four syntax-highlighting token colours
  — strings, numbers, keywords, types — were literal hexes tuned for the dark
  scheme, landing at roughly 1.9:1 contrast on a light code well. They are now
  scheme-aware and clear the 4.5:1 AA floor in both.

## 🔧 Improvements

- **Vertical rhythm is authored rather than inherited.** Code fences and display
  math were riding the browser's default margin and vendor KaTeX CSS
  respectively; they now join the same block spacing as everything else, so a
  document no longer has five competing gap sizes. The footnotes section gets a
  separating rule and its own smaller type instead of arriving unstyled.
- **Prose gets a readable measure.** Body text settles to a ~74-character line
  rather than running to 112, while tables, code blocks, figures, and display
  math keep the full-width column they need.
- **The macOS Window menu gains Close (Cmd-W)**, which simply did not exist
  before. It does the right thing for both window kinds without a special case:
  the main window hides, staying resident in the tray as it always has, and a
  reader window closes.
- **Following a link to a file reveals where it lives.** Opening a deep-linked
  document used to show the file while leaving its row hidden inside collapsed
  folders. The ancestors now open as a transient overlay, so the link never
  rewrites the expansion state you had set up.

## 🩹 Fixes

- **The commit rail no longer hands React duplicate keys.** The rail renders
  `git log --all --date-order`, which puts the topological constraint first, so
  the dates it emits are not monotonically decreasing — a branch can carry you
  back to a day already passed and then forward again, producing a second band
  for that day. Two bands for one day is correct output (collapsing them would
  mean reordering commits, which the graph forbids), so the key now identifies
  the band rather than the day. A related off-by-one that spelled the month
  0-indexed — labelling a July date as June internally — is fixed alongside it.

### Downloads

- **macOS** — `SpecForge_0.21.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.21.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.21.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.21.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.21.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.21.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server. The quickest way to run it is npm — no download, and
**no quarantine step**, because npm installs are not flagged the way browser
downloads are:

```bash
npx @avantmedia/specforge          # or: npm install -g @avantmedia/specforge
```

Only your platform's binary is fetched. It binds `127.0.0.1:4317` by default;
`--bind 0.0.0.0` (or any other interface address) publishes it on the network,
**unauthenticated** — only do this on a network you trust.

Prefer a direct download? One archive per platform — extract and run
`./specforge-serve`:

- **macOS** — `specforge-serve_0.21.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`. (This does not apply to
  the npm install above.)
- **Linux** — `specforge-serve_0.21.0_linux-x64.tar.gz` or
  `specforge-serve_0.21.0_linux-arm64.tar.gz`. Statically linked against
  musl, so one binary covers Alpine and containers as well as current and
  older glibc distributions.
- **Windows** — `specforge-serve_0.21.0_windows-x64.zip`.

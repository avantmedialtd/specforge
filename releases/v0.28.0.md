SpecForge v0.28.0

A new look and a new way to finish a review. SpecForge now has four themes with
a warmer, larger default, and the desktop app can post a pull-request review for
you.

## ✨ Highlights

- **Pick your theme.** Settings ▸ **Appearance** offers four looks, each card
  previewed with its own colours, and a scheme control: **System** (follow the
  operating system, as before), **Light** or **Dark**. The choice applies to
  every window and every running instance, and is in effect from the first
  paint.
  - **Forge** — the new default and the SpecForge brand: warm graphite, an
    ember-orange accent, Geist and Geist Mono, larger type, no shadows or
    glows.
  - **Blueprint** — drafting blue, square corners, IBM Plex Sans and Mono.
  - **Folio** — reading first: documents set in Newsreader, quiet chrome in
    Instrument Sans, a violet accent.
  - **Mycelium** — the previous look (Elevated Indigo), re-set at Forge's sizes
    and spacing, with Meslo for code.

  **The default look has changed.** An install with no stored theme now opens
  in Forge; Mycelium is one click away in Settings. Diagrams, embedded SVG, the
  activity heatmap and the browser's theme colour all follow the active
  appearance. The terminal UI keeps its own palette.
- **Review pull requests from SpecForge.** In the desktop app you can now draft
  a review — a summary, single-line inline comments, replies to existing
  threads and a decision of **Comment**, **Approve** or **Request changes** —
  and submit it to GitHub or BitBucket without leaving the pull request.
  - Comments are placed on the diff line itself: hover a line for the comment
    icon, in unified and side-by-side layouts. Ranges, outdated threads and
    anything that can no longer be placed stay in the file's preamble.
  - Nothing is sent until you confirm one exact revision of the draft in a
    native dialog, and the pull request, its commits, your credential and your
    provider identity are re-checked at every edit and at submission.
  - Drafts and operation journals are stored durably. A restart, a stale head
    or a partial failure leaves a clear state to **resume** or **abandon**,
    and a confirmed write is never repeated.
  - SpecForge still never changes your local work and never merges. The browser
    and terminal frontends stay read-only toward the provider.

## 🔧 Improvements

- **Provider tokens move to the OS keychain.** Newly saved GitHub and BitBucket
  credentials go to the operating-system credential store instead of
  `settings.json`. Existing plaintext settings and the environment-variable
  precedence keep working, and settings writes are now serialised across
  processes so a stale instance cannot bring removed plaintext back.
- **Credentials are edited on the desktop only.** The browser skin keeps the
  non-secret pull-request configuration but no longer exposes credential
  setters.
- **Sharper copy.** The README, About box and site now state the exact promise:
  SpecForge never changes local work, posts a review only from the desktop
  after explicit confirmation, and never merges.
- **The marketing site and docs adopt Forge**, with refreshed screenshots.

### Downloads

- **macOS** — `SpecForge_0.28.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.28.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.28.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.28.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.28.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.28.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server. The quickest way to run it is npm — no download, and
**no quarantine step**, because npm installs are not flagged the way browser
downloads are:

```bash
npx @avantmedia/specforge          # or: npm install -g @avantmedia/specforge
```

Only your platform's binary is fetched. It binds `127.0.0.1:4317` by default;
`--bind 0.0.0.0` (or any other interface address) publishes it on the network,
**unauthenticated** — only do this on a network you trust. Everyone who can
reach the port then sees your registered workspaces and, with a pull-request
integration enabled, the listed pull requests' changed files and
conversations, read with this host's credentials, including pull requests from
repositories this host has never cloned.

Prefer a direct download? One archive per platform — extract and run
`./specforge-serve`:

- **macOS** — `specforge-serve_0.28.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`. (This does not apply to
  the npm install above.)
- **Linux** — `specforge-serve_0.28.0_linux-x64.tar.gz` or
  `specforge-serve_0.28.0_linux-arm64.tar.gz`. Statically linked against
  musl, so one binary covers Alpine and containers as well as current and
  older glibc distributions.
- **Windows** — `specforge-serve_0.28.0_windows-x64.zip`.

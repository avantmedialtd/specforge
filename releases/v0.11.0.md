SpecForge v0.11.0

Design docs that draw themselves — plus two security fixes to the commands that read your repositories.

## ✨ Highlights

- **Mermaid diagrams render inline.** A `mermaid` code fence in any artifact — proposal, design, tasks, or capability spec — now renders as an actual diagram instead of plain source text, the way GitHub, GitLab, and Obsidian already do it. Diagrams are themed from SpecForge's own design tokens, so they read as part of the same surface as the surrounding prose in both light and dark, and they redraw when you switch your system appearance. A diagram that fails to parse degrades quietly to its source with a short note rather than blanking the pane or leaking Mermaid's default error graphic. Mermaid itself loads only when the first diagram appears, so it adds nothing to startup. The terminal client (`specforge-tui`) can't paint SVG and continues to show `mermaid` fences as text.

## 🩹 Fixes

- **Commit references can no longer be mistaken for git options.** The commands that read commit diffs and changed-file lists passed a caller-supplied commit reference to `git` positionally, with nothing marking it as data. A crafted reference could therefore be parsed as a command-line *option* rather than a revision — most seriously as `git show --output=<path>`, giving an arbitrary file create/overwrite primitive on the host. References are now validated as git object ids at the boundary and passed after `--end-of-options` at the sink, so no reference value can cause git to write, delete, or mutate files or invoke external programs.

- **Commit and artifact reads are now confined to registered workspaces.** The commands that read git history (`get_commit_graph`, `get_commit_detail`, `get_commit_diff`) and OpenSpec artifacts (`read_artifact`, and the archive listing) accepted a repository or workspace location straight from the caller and acted on it without checking it was one you had actually registered — making any `.git` directory, and any `openspec/changes/**` markdown on the host, readable. Both the desktop and web transports now authorize the location against the workspace registry and refuse anything unregistered. This matters most when the optional web server is enabled, where the same command surface is reachable over `/api/invoke` from loopback or a tailnet peer.

### Downloads

- **macOS** — `SpecForge_0.11.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.11.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.11.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.11.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.11.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.11.0_windows-x64.zip`.

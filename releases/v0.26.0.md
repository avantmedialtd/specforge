SpecForge v0.26.0

Pull requests move in. GitHub joins BitBucket in the side panes, every pull
request knows the worktree it comes from, and opening one now reads it inside
SpecForge — description, conversation, checks and a new syntax-highlighted
diff — with your review progress kept down to the hunk.

## ⚠️ Breaking

- **Two command changes for scripts that call `/api/invoke` directly.** The
  bundled desktop app and browser skin move with them; only your own scripts
  against a running `specforge-serve` need updating.
  - `get_my_pull_requests` is now `get_bitbucket_pull_requests`, and the
    `pull-requests-updated` event is now `bitbucket-pull-requests-updated`.
    `pull-request-panel-moved` keeps its name and gains a `provider` field.
  - `get_commit_detail` returns the new parsed diff model — one `DiffFile`
    per file, with its status, paths, modes, counts, and either its hunks or
    a withheld, too-large or binary state — instead of the old `CommitFile`
    list. `get_commit_diff` takes an optional `oldPath` and returns one
    `DiffFile` instead of raw patch text.

## ✨ Highlights

- **Your GitHub pull requests, beside the BitBucket ones.** A second opt-in
  panel lists the open pull requests you authored (**Yours**) and the ones
  waiting on your review, including through a team (**To review**), up to 50
  of each, most recently updated first. On top of what a BitBucket row shows,
  each row carries the author, a checks indicator (passing, failing or
  pending), a conflict marker and the count of unresolved conversations. A
  refresh — every two minutes by default — is one fixed, read-only GraphQL
  query costing 4 of GitHub's 5,000 hourly points. It is off by default:
  switch it on under **Settings ▸ Integrations ▸ GitHub** and save a token.
  The token is write-only like BitBucket's, and for a headless
  `specforge-serve` the `GH_TOKEN` or `GITHUB_TOKEN` environment variable
  takes precedence over it. The Settings copy explains the classic versus
  fine-grained trade-off, single sign-on authorisation, and how `gh auth
  token` hands you one you already have. Results GitHub withholds, typically
  an organisation enforcing single sign-on, are counted in the panel header's
  tooltip rather than shown as an error. Either panel, both or neither can be
  on, and two panels in one slot stack BitBucket first.
- **Pull requests and worktrees, linked both ways.** A change whose branch has
  an open pull request shows a `#number` chip in its header, with the draft,
  checks and conflict signals, and the instance switcher marks each linked
  instance. A linked row in either panel names its worktree and takes you to
  the change there. The link is worked out locally from your remotes and
  upstreams — no network, no new credential — and is fork-aware: a
  maintainer's `main` never links to a contributor's fork `main`, and a
  feature branch cut from `develop` never links to the `develop → main`
  release pull request. A changed remote or a newly set upstream takes
  effect without a restart.
- **Read a pull request without leaving SpecForge.** Clicking a panel row or a
  header chip opens the pull request in the center pane at its own address
  (`/pr/github/<owner>/<repo>/<number>`), so Back, Forward, reloads and deep
  links work as they do for a document. Cmd-click (Ctrl-click elsewhere), or
  the view's pop-out control, opens it in its own window — a desktop window
  or a browser tab. The view shows the description, the conversation with
  review threads anchored above the file and line they discuss, the checks
  with links out, and every changed file. When the pull request comes from a
  worktree hosting an OpenSpec change, the view names that change and one
  click takes you there. It is read-only: nothing is approved, merged or
  posted, and "Open on GitHub" / "Open on BitBucket" is one click away.
  Details are read on demand, only for pull requests the panels already
  list, and are cached, budgeted per hour and backed off together with each
  provider's panel.
- **Review progress, file by file and hunk by hunk.** Mark a file viewed, or
  work through a large one hunk by hunk: a viewed hunk folds to a single row,
  a hunk longer than 40 lines ends with a "Mark hunk viewed" row where you
  finish reading it, and a file counts as viewed exactly when all its hunks
  are, collapsing as you complete it. Marks are keyed by content, so after a
  push only the hunks that actually changed reopen — the file says "changed
  since viewed · 3 hunks to review" and unfolds just those. Marks stay on this
  machine and are never sent to either host.
- **A rich diff view, for commits and pull requests alike.** Diffs are now
  syntax-highlighted with the same grammars as code in your documents, with
  line numbers, `+`/`−` markers, a file tree that tracks where you are
  reading, and sticky, collapsible file headers. Switch between **unified**
  and **side by side** from the toolbar; the choice is remembered per surface
  and falls back to unified, saying why, where the view is too narrow.
  Characters that render as nothing — bidirectional controls, zero-width and
  tag characters — show as marked escapes, and the file header warns about
  them. Large files load when you ask, and commit detail now reads a commit
  in a fixed handful of git processes instead of one per file.
- **Big GitHub files load anyway.** GitHub leaves out the diff of any file it
  considers too big, at a low threshold. "Load diff" now fetches both
  versions of such a file and diffs them locally, up to 8 MiB per file, and
  caches the result. A file past that ceiling links to its diff on GitHub or
  BitBucket instead of dead-ending.
- **Pull-request content stays inert.** Descriptions and comments written by
  other people — or by agents — render with raw HTML left unrendered, Mermaid
  shown as source, remote images replaced by labelled links instead of
  loaded, and invisible characters made visible in titles and branch names.
  On the desktop a link opens only as an absolute `http(s)` URL. The
  pull-request window adds a content policy that refuses remote images, and
  DNS prefetching is now off in every SpecForge page.

## 🔧 Improvements

- **Settings, regrouped.** Settings now shows one group at a time —
  Workspaces, Layout, Integrations, Identity and, in the desktop app only,
  Desktop app — each at its own address (`/settings/<group>`). A group list
  sits beside the content when the pane is wide, and a one-line switcher
  above it when it is narrow. An integration that is off collapses to its
  name, one line and its switch, and its token instructions fold away once a
  credential is stored. Every on/off setting is now the same switch, text and
  number fields save on Enter or when you leave them instead of on every
  keystroke, and a rejected value is reported on the control itself. Layout
  only offers a panel position for an integration that is on.
- **Settings… on macOS.** The SpecForge menu gains *Settings…* (⌘,), which
  brings the main window forward and opens Settings.
- **The commit graph can be switched off.** **Settings ▸ Layout ▸ Commit
  history** turns the graph off once for every surface, and stops the git
  reads behind it. The right-hand rail now exists only while something
  occupies it: with nothing there, there is no column, divider or restore
  chevron, and pull-request panels left in the rail can use its full height.
- **The terminal UI gets a GitHub switch.** The `specforge-tui` Settings
  screen gains a toggle for GitHub pull requests. As with BitBucket, the
  terminal does not show the list itself.

## 🩹 Fixes

- **Commit detail tells the truth about root and merge commits.** A root
  commit now lists the files it added instead of "This commit changed no
  files", and a merge commit shows its changes against its first parent,
  labelled as such, instead of nothing. A renamed file shows as one rename
  rather than a deletion plus an addition.
- **WSL workspaces no longer pass git arguments through a shell.** Git ran
  through `wsl.exe` without `--exec`, so the Linux user's shell interpreted
  the command line. A `;`, `$(…)` or backtick in a file path or ref name from
  a repository in a WSL-hosted workspace could then run as a command when
  SpecForge read its diff or contents. Every git invocation now runs with
  `--exec`.

#### Standalone Web Server (`specforge-serve`)

The headless web server. The quickest way to run it is npm — no download, and
**no quarantine step**, because npm installs are not flagged the way browser
downloads are:

```bash
npx @avantmedia/specforge          # or: npm install -g @avantmedia/specforge
```

Only your platform's binary is fetched. It binds `127.0.0.1:4317` by default;
`--bind 0.0.0.0` (or any other interface address) publishes it on the network,
**unauthenticated** — only do this on a network you trust. Everyone who can
reach the port then sees your registered workspaces and, with a pull-request
integration enabled, the listed pull requests' changed files and
conversations, read with this host's credentials, including pull requests from
repositories this host has never cloned.

Prefer a direct download? One archive per platform — extract and run
`./specforge-serve`:

- **macOS** — `specforge-serve_0.26.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`. (This does not apply to
  the npm install above.)
- **Linux** — `specforge-serve_0.26.0_linux-x64.tar.gz` or
  `specforge-serve_0.26.0_linux-arm64.tar.gz`. Statically linked against
  musl, so one binary covers Alpine and containers as well as current and
  older glibc distributions.
- **Windows** — `specforge-serve_0.26.0_windows-x64.zip`.

SpecForge v0.27.0

Images and repositories. A changed image now shows its two versions instead of
"Binary file not shown", and the repositories around your OpenSpec one — the
API, the web client, the infrastructure — can sit in the tree beside it, with
their files, history and pull requests, even though they hold no specs.

## ✨ Highlights

- **See changed images, not "Binary file not shown".** A changed `.png`,
  `.jpg`, `.gif`, `.webp`, `.ico`, `.bmp` or `.avif` file now renders as an
  image comparison: side by side in that layout and stacked in unified, each
  version captioned, over a checkerboard where it is transparent, with its
  dimensions, its byte size and the change in size. When the two versions
  share their dimensions a per-file **Difference** mode paints every unchanged
  pixel black, so a one-pixel tweak in a regenerated icon stands out. SVG keeps
  its text diff.
  - **Commit detail** reads an image's versions as its section scrolls near.
  - **Pull requests**, on GitHub and BitBucket, offer **Show image** per file;
    each read counts against the provider's hourly detail budget.
  - **Zoom** — the control, or a click on either version — opens the file in
    its own window (a tab in the browser), where both versions pan and zoom
    together up to 32×, with crisp pixels above 100% and your platform's
    gestures: two-finger scrolling pans, a pinch zooms at the pointer, and
    ⌘+, ⌘−, ⌘0 and ⌘9 work as in Preview.
  - **Safe by construction.** The type is sniffed from the bytes, never the
    extension, and the dimensions come from the header before anything
    decodes, so a file declaring an enormous canvas — in any of the forms a
    browser's decoder honours — is refused rather than drawn. Each version is
    capped at 8 MiB and 40 megapixels, nothing is loaded from a URL, and a
    Git LFS pointer reads "Stored in Git LFS" with no read at all. Anything
    that cannot be shown links to the file's diff on its host.
- **Register repositories that have no OpenSpec folder.** In a multi-repo
  project the specs usually live in one repository while the work ships from
  its siblings. **+ Add workspace** now accepts any git repository, not just a
  folder containing `openspec/`.
  - Its row in the tree is marked **no OpenSpec** where a change count would
    be, and opens the repository's markdown file browser.
  - Its commit history appears in the rail, its uncommitted work in the dirty
    indicator, and its commits on the dashboard's heatmap and streak.
  - Your pull requests from it now lead to the local worktree they were
    checked out in.
  - Picking a subfolder registers the repository's root. A home directory
    kept under git (a dotfiles repository) or a filesystem root is refused as
    too broad to track.
  - Run `openspec init` in it later and the row becomes an ordinary one, with
    its first change in it, without a restart.
  - The terminal UI lists such repositories dimmed and explains them, and its
    add prompt accepts them too.

## 🔧 Improvements

- **Every worktree of your repositories is tracked.** SpecForge used to skip
  any worktree without an `openspec/` folder — for example one on a branch
  older than your `openspec init`. A repository registered at its root now
  tracks all of them, so their pull requests link, their markdown joins the
  file browser and their uncommitted changes show in the repository's dirty
  indicator. A repository registered at a subfolder (an `openspec/` inside a
  monorepo package) behaves as before.

## 🩹 Fixes

- **Registering a worktree SpecForge had already found no longer fails.**
  Adding a worktree that was already listed, because a sibling of it was
  registered, saved the registration but answered with an error, "register
  returned no folders". It now succeeds and returns the worktree it
  registered.
- **Pull-request file reads stay on the path they name.** A file path from a
  pull request containing a `.` or `..` segment survived the URL encoding of a
  GitHub file read, so the API host could resolve it to another of its paths
  with your token attached. Such a read is now refused before anything is
  sent.

- **macOS** — `SpecForge_0.27.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.27.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.27.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.27.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server. The quickest way to run it is npm — no download, and
**no quarantine step**, because npm installs are not flagged the way browser
downloads are:

```bash
npx @avantmedia/specforge          # or: npm install -g @avantmedia/specforge
```

Only your platform's binary is fetched. It binds `127.0.0.1:4317` by default;
`--bind 0.0.0.0` (or any other interface address) publishes it on the network,
**unauthenticated** — only do this on a network you trust. Everyone who can
reach the port then sees your registered workspaces and, with a pull-request
integration enabled, the listed pull requests' changed files and
conversations, read with this host's credentials, including pull requests from
repositories this host has never cloned.

Prefer a direct download? One archive per platform — extract and run
`./specforge-serve`:

- **macOS** — `specforge-serve_0.27.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`. (This does not apply to
  the npm install above.)
- **Linux** — `specforge-serve_0.27.0_linux-x64.tar.gz` or
  `specforge-serve_0.27.0_linux-arm64.tar.gz`. Statically linked against
  musl, so one binary covers Alpine and containers as well as current and
  older glibc distributions.
- **Windows** — `specforge-serve_0.27.0_windows-x64.zip`.

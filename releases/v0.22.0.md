SpecForge v0.22.0

The reading column becomes yours, the Dashboard's Overview band earns its
place, and the marketing site moves in next door to the product it documents.

## ⚠️ Breaking

- **The named-people roster is gone, and its stored data goes with it.** The
  Settings *People* section — where you could name and merge other contributors
  — existed to make the per-author leaderboard read well, and the leaderboard
  is removed in this release too. Its only other consumer was the commit
  garden, which used roster names for nothing a frontend actually rendered.
  **The loss is permanent**: an existing `settings.json` still carries its
  `people` array, and the first write of *any* setting after upgrading drops
  it irrecoverably — expanding a single tree node is enough. Downgrading will
  not bring it back. After this release nothing anywhere lets you name another
  person; every non-you author is presented by their raw git identity. Your own
  identity is untouched — display name, aliases, and the *Identity* section all
  stay exactly as they were.

## ✨ Highlights

- **Choose your reading width.** The document column was a well-reasoned pair of
  literals — an 880px cap with prose held to 74 characters — and no way to
  change either. It is now a four-rung preset ladder in Settings, stored as one
  global preference. `Full` lets objects (tables, fenced code, diagrams, display
  mathematics) fill the pane while prose keeps a readable measure, so a
  ten-node flowchart on a wide display gets the room it needs instead of being
  scaled down to protect a column that had no reason to be narrow; the narrow
  rungs give you the classic tighter line. The preset is correct on the very
  first paint, and changing it reaches reader windows that are already open —
  in the desktop app and in the browser alike.
- **A Dashboard Overview band worth reading.** The 64px commits strip — bars
  wider than they were tall, no baseline, no scale, unreadable without hovering
  — is gone, and the band is rebuilt around the per-repository breakdown, now a
  ranked, capped, full-width card. Repositories are ordered by active work
  rather than by registration order, so the two with something in flight no
  longer sit twelfth and thirteenth beneath ten empty tracks. At most five rows
  render, with a remainder line saying how many were withheld and whether any
  of them carries active work; rows with nothing in flight drop their bar
  entirely rather than drawing an empty rectangle. The lifecycle figures move
  onto the band's divider rule, and **Today's ships is promoted above the
  heatmap** — the desktop's section order now matches the terminal UI's.
- **Real downloads, above the fold.** The site's "Get SpecForge" button used to
  teleport four and a half screens down to a section that described platforms
  without linking a single file, past four cells that looked exactly like a
  segmented control and did nothing when clicked. The hero now carries a
  primary download control that links an actual, version-pinned asset, the
  inert cells are gone, and everything that looks like a download performs one.
- **A changelog on the site.** A new `/changelog` route renders the current
  release's notes in full, followed by every earlier release with its version,
  date and tagline. Thirty-one releases of carefully written notes had been
  published in exactly one place — GitHub Release bodies — so neither a
  prospect nor an existing user could answer "what changed" without leaving
  the site.

## 🔧 Improvements

- **The marketing site now lives in this repository**, at `site/`. It documents
  this repo's binaries, flags, ports and platform matrix, so a flag renamed here
  no longer needs a second change in a second repository that nothing forces
  anyone to make — the docs can move in the same commit as the behaviour they
  describe. Publishing runs on GitHub Actions with OIDC role assumption instead
  of a long-lived IAM user.
- **The site header's GitHub link is now GitHub's mark**, with an accessible
  name of "GitHub" so it is announced exactly as the word was. It marks the one
  item in the nav that leaves the site, and returns most of a nav label's width
  to a header that had about 3px of slack at 390px.
- **The commit garden's caption is honest again.** With the roster gone it reads
  "N authors" rather than "N people", since a contributor committing under two
  git identities now draws in two colours and counts as two.

## 🗑 Removed

- **The per-author leaderboard**, in both the desktop app and the terminal UI.
  It was the only surface in SpecForge that scored people against one another,
  it informed no decision, and on a solo machine it never rendered at all.
- **The Overview commits chart** and the fourteen-day commit-bucket payload
  behind it. This drops one signal deliberately: the chart was the only view of
  *every* author's daily commit volume, since the heatmap is scoped to you. The
  commit garden still shows today's per-author, per-repository detail.

## 🩹 Fixes

- **The change-identity header's trailing cluster now reaches the column edge.**
  The last-changed label came to rest roughly 206px short of the document
  column's trailing edge with nothing visible beside it to explain the stop —
  two elements on one flex line each declared `margin-left: auto`, and flexbox
  splits free space equally between them, so half of it was being held by a
  control that is invisible at rest.

### Downloads

- **macOS** — `SpecForge_0.22.0_universal.dmg` (Apple Silicon + Intel).
  This build is **unsigned**: on first launch, right-click the app ▸ **Open** and
  confirm, or clear the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/SpecForge.app`.
- **Windows** — `SpecForge_0.22.0_x64-setup.exe` (installer, recommended —
  ensures the Microsoft Edge WebView2 runtime) or
  `SpecForge_0.22.0_x64-portable.exe` (single file; uses the system WebView2
  runtime, preinstalled on Windows 11 and maintained Windows 10 — use the
  installer if your machine lacks it).
- **Linux** — `.deb` or `.AppImage`.

#### Terminal UI (`specforge-tui`)

The standalone terminal client, one archive per platform — extract and run
`./specforge-tui`:

- **macOS** — `specforge-tui_0.22.0_macos-universal.tar.gz` (Apple Silicon +
  Intel). **Unsigned**, and a terminal binary has no right-click ▸ Open dialog,
  so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-tui`.
- **Linux** — `specforge-tui_0.22.0_linux-x64.tar.gz`.
- **Windows** — `specforge-tui_0.22.0_windows-x64.zip`.

#### Standalone Web Server (`specforge-serve`)

The headless web server. The quickest way to run it is npm — no download, and
**no quarantine step**, because npm installs are not flagged the way browser
downloads are:

```bash
npx @avantmedia/specforge          # or: npm install -g @avantmedia/specforge
```

Only your platform's binary is fetched. It binds `127.0.0.1:4317` by default;
`--bind 0.0.0.0` (or any other interface address) publishes it on the network,
**unauthenticated** — only do this on a network you trust.

Prefer a direct download? One archive per platform — extract and run
`./specforge-serve`:

- **macOS** — `specforge-serve_0.22.0_macos-universal.tar.gz` (Apple
  Silicon + Intel). **Unsigned**, and a terminal binary has no right-click ▸
  Open dialog, so clear the quarantine flag before the first run:
  `xattr -dr com.apple.quarantine specforge-serve`. (This does not apply to
  the npm install above.)
- **Linux** — `specforge-serve_0.22.0_linux-x64.tar.gz` or
  `specforge-serve_0.22.0_linux-arm64.tar.gz`. Statically linked against
  musl, so one binary covers Alpine and containers as well as current and
  older glibc distributions.
- **Windows** — `specforge-serve_0.22.0_windows-x64.zip`.
